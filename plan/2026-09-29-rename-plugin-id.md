# Plan: Plugin id `nixarchy.hyprlandsettings` and a NixOS-first README

Branch `feat/rename-plugin-id`, stacked on #4 (`feat/rename-display-name`).
This PR also carries the doc parts of the approved restart-safety spec
(`spec/2026-09-29-shell-restart-safety.md`). One commit per step, each
naming its step.

## Decisions carried from the approved specs

- **New id:** `nixarchy.hyprlandsettings`. It changes in:
  - `manifest.json`;
  - the `Service.qml` `pluginId` fallback;
  - the `Panel.qml` `hide()` fallback;
  - the `Engine.js` `HEADER` ("generated by the nixarchy.hyprlandsettings
    plugin");
  - `flake.nix`: the link path
    `xdg.configFile."omarchy/plugins/nixarchy.hyprlandsettings"`, the
    binds' `toggle` target, and comments;
  - the skill's install check;
  - `AGENTS.md` invariant 1.
- **Unchanged:**
  - the state paths;
  - the IPC target `hyprforge`;
  - `hypr.hyprforge` and the hook;
  - `X-Hyprforge-Managed`, `hyprforgeProfile` and `hf:*`;
  - the skill name.
- **Migration order:**
  1. `omarchy plugin disable aziz.hyprforge`, while the old one is still
     installed;
  2. move any old copy **out of** `~/.config/omarchy/plugins`;
  3. switch;
  4. `omarchy-shell shell rescanPlugins`, then wait for `ping`;
  5. `omarchy plugin enable nixarchy.hyprlandsettings`.
- **The restart rule** (restart-safety spec): after install, update or
  remove, no `omarchy restart shell`. Run `rescanPlugins` and wait with
  `until omarchy-shell shell ping >/dev/null 2>&1; do sleep 1; done`. If a
  restart is unavoidable: wait for idle, keep the output, and check `ping`
  after. Nixarchy #953 is the background.
- **README rewrite, NixOS-first**, in the section order of spec §3:
  1. intro and credit;
  2. install on NixOS, with an options table and a first-run checklist;
  3. updating;
  4. migrating;
  5. using it: features, keys, CLI and colors, with the menu/binding
     examples using the new id;
  6. how it works and why it's safe, plus the Nix points;
  7. what this fork adds;
  8. uninstall on NixOS;
  9. development;
  10. other distributions (two lines);
  11. credits and license.
- **`AGENTS.md` invariant 9** (the restart rule, and moving old copies out
  of the plugins dir). **The skill** gets a "busy after install/update:
  wait, don't restart" note.
- **Branches:** rebase #2, #3 and #4 onto the current
  `feat/nixos-packaging` (with the migration correction d203594), and
  force-push with lease. Then this branch is rebased onto the new #4 and
  merges #2 and #3. The merge order is #1 → #2 → #3 → #4 → this one.

## Steps

1. **Rebase the stack.** In order:
   - rebase `ci/checks-lint-test`, `docs/agents-md-skill` and
     `feat/rename-display-name` onto `feat/nixos-packaging`, and
     `git push --force-with-lease` each;
   - rebase this branch onto `feat/rename-display-name`, then merge
     `ci/checks-lint-test` and `docs/agents-md-skill` into it.

   → verify: none of the four branches contains `aziz.hyprforge.bak`, and
   `nix flake check` passes on this branch. PR #2's CI is green again after
   its push.

2. **Id in code**: `manifest.json`, the `Service.qml`/`Panel.qml`
   fallbacks, `Engine.js` `HEADER`, and the `flake.nix` link path, binds
   and comments.
   → verify: tests pass; `nix flake check` passes; the module eval shows the
   `omarchy/plugins/nixarchy.hyprlandsettings` entry, and the binds text
   toggles the new id.

3. **Agent docs**: `AGENTS.md` invariant 1 (new id) and the new invariant 9
   (restart rule); the skill's install check with the new id, and the
   busy-after-install note.
   → verify: `grep -n "aziz.hyprforge" AGENTS.md skills/` shows only the
   "replaced" note.

4. **README rewrite**: write it fresh in the spec's section order, and
   carry over every fact from the current README and #2/#3 (option names,
   commands, keys, safety points, credits). Changes compared with the old
   one:
   - the new id everywhere;
   - no "restart shell" steps;
   - the migration steps;
   - the options table;
   - "What this fork adds".

   → verify:
   - `grep -n "restart shell"` shows only the #953 explanation;
   - `grep -n "aziz.hyprforge"` shows only the migration steps;
   - every `programs.nixarchy-hyprsetting.*` option in `flake.nix` is in
     the options table (a scripted check);
   - every `omarchy-shell hyprforge` command in `Service.qml`'s IpcHandler
     is listed (a scripted check);
   - the credit line and the upstream link are present.

5. **Live migration on this host**, following the new README **exactly**,
   with no `omarchy restart shell`:
   - first, the agent bus: `read_new` on `#agents:freundcloud.org.uk`, and
     `post` the host, what is changing and roughly how long (~10 min), as
     the host hook requires;
   - back up `~/.config/omarchy/shell.json`, `~/.config/hypr/hyprforge/`,
     `hyprforge.lua`, `hyprforge.desktop`, and the plugin dir (moved into
     the scratchpad, out of the plugins dir);
   - run README steps 1–5. Since this host doesn't have the HM module wired
     in, step 3 is simulated by creating the store symlink
     `~/.config/omarchy/plugins/nixarchy.hyprlandsettings` → the
     `nix build` output, which is what HM would link;
   - wait for `ping` after every step that changes plugin folders;
   - check:
     - `listPlugins` has `nixarchy.hyprlandsettings` enabled, and
       `aziz.hyprforge` is absent or disabled;
     - the launcher `Exec=` uses the new id;
     - `omarchy-shell hyprforge set/unset` works;
     - `omarchy-shell hyprforge open`/`close` works;
     - `state.json` cfg is unchanged;
     - `configerrors` is empty;
     - the bar is present throughout (layers sampled).
   - Also try the stale-entry case: what removes a leftover
     `aziz.hyprforge` entry once its plugin is gone? Document what works.
   - Restore the same careful way, in reverse (disable the new id, remove
     the symlink, put the original dir back, `rescanPlugins`, wait, enable
     `aziz.hyprforge`, restore the backed-up files). Check with
     `diff`/`cmp` that `shell.json`, the state dir, `hyprforge.lua` and
     the desktop file are byte-identical, and that `ping` answers.
   - Record the results here. Post "done" on the bus.

6. **Push and PR**: push this branch and open a PR with base
   `feat/rename-display-name`, linking this plan and the restart-safety
   spec, and noting the merge order and the included #2/#3 commits.

## Rollback

- `git revert` this PR's commits. The rebased #2/#3/#4 keep their own
  content.
- Host: the step 5 backups restore everything. If the shell ever stops
  answering for more than 60 s, stop, and restore `shell.json` and the
  original plugin dir first. Only then consider a restart, after waiting
  for idle, keeping its output, and checking `ping`.
