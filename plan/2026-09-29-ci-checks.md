# Plan: CI that checks, lints and tests every change

Branch `ci/checks-lint-test`, based on `feat/nixos-packaging` (PR #1). Its
PR is based on that branch and retargeted to `main` after #1 merges. One
commit per step, each naming the step.

## Decisions carried from the approved spec

- All checks live in `flake.nix`. CI runs only `nix flake check -L`.
- The checks are:
  - `package`: the plugin package;
  - `tests`: `node test/run.js` (the current `default` check, renamed);
  - `lint`: one derivation running, in order:
    1. `nixfmt --check` on all `*.nix`;
    2. `statix check .` and `deadnix --fail .`;
    3. `qmllint` on every `*.qml`, failing **only** if the output contains
       `[syntax]` (qmllint exits 0 on syntax errors, and floods
       import-resolution warnings in the sandbox);
    4. `node test/embedded-sh.js <outdir>` extracts `BoundedRead.qml:script`,
       `SafeWriter.qml:script`, `Service.qml:installScript` and
       `Panel.qml:hookScript`, and fails if any is missing; each script then
       gets `sh -n` and `shellcheck -s sh`;
    5. `luac -p baseline.lua`.
- `formatter.<sys> = pkgs.nixfmt`.
- Workflow `.github/workflows/ci.yml`:
  - triggers: push to `main`, `pull_request`, weekly cron
    `0 6 * * 1`, `workflow_dispatch`;
  - `permissions: contents: read`;
  - `concurrency` per ref, with cancel-in-progress;
  - `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1` (v7.0.1);
  - `cachix/install-nix-action@13d8dd58da0234aa297dedd986986ccb8e7f3e24`
    (v31.11.1);
  - `nix flake check -L`.
- No auto lock-bump job, and no `test/live.js` in CI.

## Steps

1. **`test/embedded-sh.js`**: a list of `[file, property]` pairs. For each,
   match `readonly property string <prop>: [ … ].join`, evaluate the array
   with comments stripped, and write `<outdir>/<file>-<prop>.sh` with a
   `#!/bin/sh` header. Exit 1 with the missing name if there's no match.
   → verify: run it into the scratchpad; 4 files; `sh -n` and `shellcheck`
   are clean. Renaming `hookScript` in a scratch copy makes it exit 1.

2. **`flake.nix` checks and formatter**: rename `checks.default` to
   `checks.tests`, and add `checks.package` and `checks.lint`. The `lint`
   inputs are `nixfmt`, `statix`, `deadnix`, `qt6.qtdeclarative`, `nodejs`,
   `shellcheck` and `lua`. It copies the source to a writable dir, since
   statix/deadnix read the tree. Add `formatter`.
   → verify: `nix flake check -L` fails only on the two known findings
   (nixfmt and statix).

3. **Fix the findings**: in `flake.nix`, change `version = (…).version` to
   `inherit (…) version`, then run `nix fmt`.
   → verify: `nix flake check -L` is green.

4. **Negative checks** (local only, reverted, not committed). Each must turn
   `lint` red:
   - `var x = ;` added to a component QML;
   - an unbalanced `'` in SafeWriter's script;
   - `hookScript` renamed;
   - a mis-indented line in `flake.nix`.

   → verify: 4× red, then green after `git checkout .`.

5. **Workflow**: add `.github/workflows/ci.yml` as decided.
   → verify: `nix run nixpkgs#actionlint -- .github/workflows/ci.yml` is
   clean.

6. **README note**: under Development, one line saying
   `nix flake check` is what CI runs and `nix fmt` formats the code.
   → verify: renders; no other README changes.

7. **Push and PR**: push the branch and open a PR with base
   `feat/nixos-packaging`, linking the intent, spec and plan.
   → verify: the Actions run on the PR is green. If it's red, fix it in the
   step that caused it and record the deviation here.

## Tests

- `nix flake check -L` passes locally and in Actions.
- The negative checks in step 4 each fail as expected.
- `actionlint` is clean.

## Rollback

Delete `.github/workflows/ci.yml` and `git revert` the flake commits. No host
or runtime change is involved.
