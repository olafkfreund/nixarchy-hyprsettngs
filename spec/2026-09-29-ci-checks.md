# Spec: CI that checks, lints and tests every change

## Design

All checks live in `flake.nix`, and CI only runs `nix flake check`, so
`nix flake check` on a laptop is exactly the CI run.

### Flake checks (per system)

| Check | Runs | Fails on |
|---|---|---|
| `package` | `self.packages.<sys>.default` | the plugin package not building |
| `tests` | `node test/run.js` (the existing `default` check, renamed) | any test failure |
| `lint` | the linters below, in one derivation | any finding |

`lint` runs, in order:

1. `nixfmt --check` on every `*.nix`.
2. `statix check .` and `deadnix --fail .`.
3. `qmllint` on every `*.qml`. qmllint **exits 0 even on a syntax error**
   (verified: `var x = ;` gives `Expected token … [syntax]` and exit 0), and
   without the Quickshell imports it prints thousands of unresolved-type
   warnings. So the check greps the output for the `[syntax]` category only,
   and fails if it finds any.
4. The embedded shell scripts: `BoundedRead.qml` `script`, `SafeWriter.qml`
   `script`, `Service.qml` `installScript` and `Panel.qml` `hookScript`.
   These are the code that writes the user's files. A new
   `test/embedded-sh.js` extracts each one (the same `[...].join("\n")`
   evaluation QML does) into `$TMP`. It **fails if a listed property is
   missing**, so a rename can't silently drop it from the check. Each script
   then gets `sh -n` and `shellcheck -s sh`. All four pass both today
   (verified).
5. `luac -p baseline.lua`.

Also `formatter.<sys> = pkgs.nixfmt`, so `nix fmt` formats in place.

### Workflow `.github/workflows/ci.yml`

- Triggers: `push` to `main`, `pull_request`, `schedule` weekly (Monday
  06:00 UTC) and `workflow_dispatch`.
- `permissions: contents: read`. No secrets.
- One job on `ubuntu-latest`:
  - `actions/checkout`, pinned to its v7.0.1 SHA
    `3d3c42e5aac5ba805825da76410c181273ba90b1`;
  - `cachix/install-nix-action`, pinned to its v31.11.1 SHA
    `13d8dd58da0234aa297dedd986986ccb8e7f3e24`;
  - `nix flake check -L`.
- `concurrency` cancels superseded runs on the same ref.

### Fixes the new linters require (found by running them now)

- `flake.nix` isn't nixfmt-formatted: run `nix fmt`.
- statix: `version = (builtins.fromJSON …).version` becomes
  `inherit (builtins.fromJSON …) version`.
- deadnix: clean.

## Alternatives rejected

- **Separate workflow steps per tool** (setup-node, apt shellcheck, …): the
  local and CI runs would drift, which the intent forbids.
- **`qmllint --max-warnings 0`** or strict mode: it fails on thousands of
  import-resolution warnings, because the Quickshell and `qs.*` modules
  aren't available in the sandbox. That's noise.
- **Bundling Quickshell into the check so qmllint resolves types**: heavy,
  and it still couldn't resolve Omarchy's `qs.Commons` / `qs.Ui` modules.
  Syntax errors are the real risk.
- **Auto lock-bump PR job**: rejected at intent approval (least privilege).
- **Running `test/live.js` in CI**: it needs a live Hyprland.

## Risks

- The weekly run can go red because nixpkgs moved. It checks against the
  pinned `flake.lock`, so that happens only if the lock is bumped, and that's
  the point.
- The grep-based QML check only catches what qmllint classes as `[syntax]`.
  A type error in a binding still ships. That's accepted, and documented in
  the check.
- `embedded-sh.js` evaluates the array literal from the QML source with
  `eval`. The input is this repo's own file inside the Nix sandbox, and the
  same pattern was used by hand this session.

## Verification

- `nix flake check -L` passes locally after the fixes.
- Negative checks, run locally and not committed. Each one must turn the
  check red, then be reverted:
  - a `var x = ;` in a QML file;
  - an unbalanced quote in `SafeWriter`'s script;
  - renaming `hookScript`;
  - a stray unformatted line in `flake.nix`.
- After pushing: the workflow runs on the PR and is green.
