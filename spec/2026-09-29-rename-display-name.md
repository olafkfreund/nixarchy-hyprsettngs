# Spec: Show the plugin as "Nixarchy Hyprland Settings"

## Design

This covers user-visible text only (intent Q1). The name is always the full
"Nixarchy Hyprland Settings" (Q3). No IPC alias (Q2).

### Changes

| File | Where | New text |
|---|---|---|
| `manifest.json` | `name` | `Nixarchy Hyprland Settings` |
| `manifest.json` | `description` | Starts with "Nixarchy Hyprland Settings (based on Hyprforge by Aziz / AbdulazizAlwabel): a Hyprland studio for Omarchy: …". The rest stays, and "SUPER+SPACE › Hyprforge" becomes "SUPER+SPACE › Nixarchy Hyprland Settings" |
| `Panel.qml` | title `text: "Hyprforge"` | `Nixarchy Hyprland Settings`, plus `elide: Text.ElideRight` and `Layout.fillWidth: true`, because the title is about 3× longer and must not overflow a narrow or docked panel |

### Unchanged (contract, verified)

- The plugin id `aziz.hyprforge`, the IPC target `hyprforge`, and every path
  (`~/.config/hypr/hyprforge{.lua,/}`, `~/.cache/hyprforge`,
  `hyprforge.desktop`).
- The Lua module `hypr.hyprforge`. `hasHook`/`removeHook` match
  `"hypr.hyprforge"`, not the comment, so existing hook lines with the old
  comment keep working, and Disconnect still removes them.
- `X-Hyprforge-Managed=true`, which `installScript` uses to recognise and
  rewrite its own launcher file. With it kept, the existing launcher file is
  rewritten in place with the new `Name=`.
- The `hyprforgeProfile` clipboard key.
- The `hf:*` keys and the code comments.

### Effect on existing installs

- The first commit after the update renders a new `HEADER`, so
  `hyprforge.lua` is rewritten once (header lines only) and Hyprland reloads
  once. It goes through the normal eval → write → reload path.

## Alternatives rejected

- **Renaming the id, IPC or paths**: breaks keybindings, the hook and state
  for existing installs. Excluded at intent.
- **A shorter name in notifications**: declined at intent (Q3).
- **Changing the `X-Hyprforge-Managed` marker**: the new code wouldn't
  recognise the old launcher file, so it would skip it (it refuses to touch
  unmanaged files), and users would keep a stale "Hyprforge" entry.

## Risks

- The long title in the panel header: mitigated with `elide`. It's checked
  visually in both dock positions.
- Launcher search for "hyprforge": mitigated with `Keywords`.
- PR #2's lint and PR #1's tests must stay green. The QML syntax check
  covers the edited files once #2 is in.
