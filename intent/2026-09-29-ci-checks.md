# Intent: CI that checks, lints and tests every change

## Problem

Nothing runs automatically. `node test/run.js`, `nix flake check` and the
build only run when someone remembers to run them locally, and PR #1 was
verified by hand. There is also no linting:

- Nix files aren't format- or lint-checked.
- The QML files are never parsed outside a running shell. A syntax error only
  shows up as a broken panel after `omarchy restart shell`.
- The shell snippets embedded in QML (SafeWriter, hookScript), which guard
  the user's `hyprland.lua` and state files, are never syntax-checked. They
  were checked by hand this session.
- `baseline.lua` and the Lua that `Engine.js` generates are only checked by
  `luac -p` inside `test/run.js`, which is fine but not run in CI.

## Proposed outcome

Every push and PR to `main` gets a GitHub Actions run that fails on:

- a failing `nix flake check` (package build, HM module eval, offline tests);
- Nix formatting or lint problems;
- a QML syntax error;
- a syntax error in the embedded shell scripts;
- a syntax error in `baseline.lua`.

The same checks run locally with one command, so CI isn't the first place a
problem is seen.

## Affected users and systems

- This repo: `.github/workflows/`, likely `flake.nix` (the checks), possibly
  small fixes if the new linters flag real problems.
- GitHub Actions minutes on `olafkfreund/nixarchy-hyprsettngs`.
- Not affected: the plugin's runtime behaviour, or any host.

## Constraints

- It must not need a running Hyprland or Omarchy. `test/live.js` stays
  local-only.
- It must not require secrets. It should use only public actions with pinned
  versions, and least-privilege `permissions:` (`contents: read`).
- Lint must be signal, not noise. `qmllint` without the Quickshell imports
  reports thousands of "unresolved" warnings (seen this session), so the QML
  check must fail only on real syntax errors.
- Checks are defined once, in the flake, and CI calls them, so local and CI
  can't drift.
